# 0007 · 工作区级 AGENTS.md 作为默认写作指令

- 日期：2026-11-13
- 状态：已采纳

## 背景

全场写作指令原本只从一个地方读：会话目录里的 `AGENT.md`（或 `<模型名>.md`）。每场戏新建时写入一份模板说明，导演要写自己的文风、禁忌、尺度，就得逐场去改那个文件。

实际使用里，导演会把规则放在工作区根目录、文件名取 `AGENTS.md`——这是很多编码工具的习惯，也符合「这个工作区就是这本书」的直觉。但代码只读会话目录，于是这份规则静默失效：模型照旧按默认模板写，导演却以为它生效了。

## 决策

1. **每回合读两层指令。** 先读工作区根的 `AGENTS.md`（其次单数 `AGENT.md`），再读会话目录的 `<模型名>.md`（其次 `AGENT.md`）；两段按顺序拼起来，一起放进 system 的同一个位置（剧场契约之后、演员表之前）。
2. **两层都现读，不做快照。** 改工作区文件，所有戏下一回合立即生效；改会话文件，只影响这一场。不复制、不缓存。
3. **会话的默认模板不算指令。** 新建会话时写入的模板说明（内容与 `DEFAULT_AGENT` 相同）不进 prompt；导演真写了内容才生效。
4. **文件名兼容。** 工作区层 `AGENTS.md` 优先、单数 `AGENT.md` 兜底；会话层保持 `<模型名>.md` 优先、`AGENT.md` 兜底。

## 理由

- **工作区是书的容器。** 一份规则管整本书，比每场戏复制一遍自然；会话层保留给「这一场想换文风」的例外。
- **现读而不是快照**：指令是「给模型的行为规则」，导演改完期待立刻按新规则写；这与状态模板「套用即快照、改模板不动已开的戏」相反，因为模板是数据资产，指令是行为约定。
- **忽略默认模板**：模板那几句话是占位说明（「可以写：文风、禁忌…」），进 prompt 只是噪音，还会让模型误以为这是对它下的要求。
- **后出现者更具体**：两段拼接时工作区在前、会话在后，模型读到的最后一段更近，天然形成「本场覆盖默认」的倾向。

## 后果

- 正面：工作区放一份 `AGENTS.md`，所有戏立刻受它约束；已有会话无需迁移；单场仍可再补规则。
- 负面：工作区文件改动会影响所有戏（这是期望，但误改也会全盘生效）；文件很长时每回合都占 context（例如 1.4 万字符 ≈ 数千 token），成本随它线性增长；两段冲突时，优先级靠「后出现」而不是硬保证，模型仍可能各取一半。

## 被否决的方案

- **开戏时把工作区规则复制进会话 `AGENT.md`**：旧会话不更新，改一次工作区规则要逐场同步，违背「改一处全生效」的诉求。
- **只读工作区、不读会话**：单场戏没法覆盖默认，也丢掉 `<模型名>.md` 这个按模型微调的入口。
- **拼进剧场契约**：契约是代码注入、用户不可编辑的最终约束，不能混入用户内容，否则「契约 > 用户指令」的优先级就不成立了。
