# 0003 · 选区改写：只重写选中的一小段，直接落盘

- 日期：2026-11-13
- 状态：已采纳

## 背景

ADR 0001 给了两种改稿粒度：**重新生成**（用原大纲重写整回合）和**编辑**（把整段情节换成 textarea 手改）。但导演真实遇到的情形是「读到一句别扭的话，只想改这一句」：重新生成会把别处也换掉，手改则要把整段重打一遍、还得自己找句子。于是需要夹在两者之间的第三种粒度：在阅读态选中一小段文字，说一句怎么改，让 AI 只重写这一段。

## 决策

1. **新接口 `POST /api/sessions/:id/turns/:turn/rewrite`**，body `{ selected, instruction, before, after }`；服务端读原文、定位选区、调一次模型、拼回新全文、原子写盘，返回 `{ rewritten, memoryStale, messages }`。不走 SSE，前端只等结果。
2. **选区定位在服务端做**：把原文与「选区前 30 字 + 选区 + 选区后 30 字」一起做去空白归一后匹配；命中唯一才替换。找不到或不唯一一律 400「这段原文已经变了，重新选一次」，绝不猜位置、绝不写盘。
3. **复用编辑的落盘语义**：改写后该回合 `edited: true`、`nextOptions` 作废、已压进摘要的回合带 `memoryStale` 提示。界面给一次内存内的「撤销」（把替换前的整段原文写回），刷新即失效；撤销不恢复 `edited` 与选项。
4. **改写按指令来，允许动事实**：提示不写死「只许改表达」，而是要求按导演那句话改，并附上「本回合完整情节 + 本回合大纲 + 上一回合结尾 300 字 + 下一回合大纲与开头 300 字」，让模型自己把衔接处理掉。
5. **调用不带思考强度**，与后续选项/记忆压缩一致；模型用本场当前的模型与供应商。
6. **结果保护**：模型输出先清洗（首尾引号、「改写后：」前缀行、Markdown 粗体、零宽字符）；清洗后为空返回 400，超过 2000 字返回 400，两种情况原文一个字不动。

## 理由

- **直接替换而不做预览确认**：作者自己当导演，要的是「改完接着读」；每次弹一个新旧对照让用户点「确认」，比改坏了点撤销更慢。撤销只保留在内存里，磁盘版本历史交给 git（ADR 0001 已定）。
- **定位失败就报错**：错位替换会静默毁掉整段情节，代价远高于让导演重新选一次。
- **撤销不恢复 `edited`/选项**：后续剧情选项是针对旧文写的建议，恢复它们等于把旧文当新文；`edited` 是「这一回合被动过」的事实，撤销文字不等于撤销这件事。
- **允许指令改事实**：导演说「改成他没听见」时，硬写「只许改表达」会让模型阳奉阴违；与其禁止，不如把前后文一起给它，让它把衔接做在该段之内。代价是改写后的文字可能与本回合已记录的角色状态不再对应。
- **服务端定位而非前端算 offset**：界面渲染文本（段首缩进被剥掉、跨段换行数不同）与磁盘原文的字面位置对不上，前端算出的 offset 会漂。

## 后果

- 正面：任意回合、任意连续的一小段都能就地按指令改；改中间段时会参考下一回合，减少与后文的矛盾；不需要新回合、不触发选项/状态/记忆重新生成。
- 负面：改写动了事实之后，本回合的角色状态不回算，状态依据会与原文脱节（借 `edited` 标记在状态面板里提示）；这次改写不产生任何版本记录，想回退到改写前只能找 git 或点撤销（仅当前页面）。

## 被否决的方案

- **复用 `PATCH /turns/:turn` 传整段新文本**：定位与模型调用仍得在前端做，等于把拼装逻辑放进界面；而且前端拿不到稳定的原文 offset。
- **前端传 offset**：渲染文本与原文的空白/缩进不同，跨段选区更对不上，必然出现错位。
- **给 2～3 个候选让导演挑**：多一次决策，与「改完继续读」的目标相悖；想再改一版，重新划一次、重说一句即可。
- **只允许改最后一回合**：选区改写的价值恰恰在「读到中间哪句别扭就改哪句」，限制回合数就退回「删了后面重写」。
