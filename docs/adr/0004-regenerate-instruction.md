# 0004 · 重新生成时带一句重写要求

- 日期：2026-11-13
- 状态：已采纳

## 背景

ADR 0001 让最后一回合可以「重新生成」：复用已落盘的大纲、整段重写、覆盖旧稿。但导演真实想改的常常是方向而不是整段：「大纲不动，这一遍写冷一点」「少写心理，多写动作」「换个开头」。已有的两条粒度都接不住：选区改写（ADR 0003）只改一小段，编辑要手打整段，而重新生成只能原样重来一遍、结果往往和上一稿差不多。

## 决策

1. **重写要求是可选的一次性参数。** `POST /turns/regenerate` 增加可选 body `{ instruction }`；省略或空串等于原来的「按原大纲再写一遍」，一键重写的行为保持不变。
2. **要求不改大纲、不改回合结构。** 它只随这一次模型调用进入 prompt，不写进 `director` 记录，不产生新回合号，也不影响之后回合能看到的历史。
3. **注入位置：user 消息末尾。** 在【本回合大纲】之后加一段【重写要求】，写明「大纲不变，按这条重写这一回合」；system 里的剧场契约仍然压在最上面。
4. **要求随新稿落盘。** 新情节记录的 `instruction` 字段存下这句话（可选字段，旧记录没有照常读），界面在情节下方标「按「…」重写」，导演能回看这一稿是按什么要求写的。失败或中断时没有新稿，也就没有这条记录。
5. **入口是导演条下的就地输入框。** 点「重新生成」展开，Enter 提交、Shift + Enter 换行、Esc 或「取消」收起；重写期间只读，失败或中断时保留内容，成功后退回阅读态。
6. **长度上限 500 字。** 超出返回 400、不写盘、不调模型——要求是一句话，超长多半是误把正文粘了进来。

## 理由

- **要求不写进大纲**：大纲是这一回合的稳定身份，重新生成、失败重试、删掉重建都以它为准。把一次性的要求并进去，会让再次重写时把上一次的要求也照着念。
- **放在 user 末尾**：模型对末段指令最敏感，正好用来定这一遍的写法；同时它只是 user 内容，不会越过 system 里的契约（只写小说正文、不引入新角色等）。
- **留空可用**：「再写一版看看」仍是最常见的用法，强制填要求会把一键操作变成填表。
- **落 `instruction` 而不是另存**：它和那一稿同生共死，删除或再次重写这一回合时不需要同步清理第二份文件；界面也因此能解释这一稿的来源。
- **就地输入**：项目里编辑回合、改状态值、选区改写都是就地展开；重写时导演还在读上一稿的同一个位置，不该跳出一个盖住正文的弹窗。

## 后果

- 正面：一次调用就能换方向重写整段，不必「先删后写」也不用手打；失败或中断时输入框还在，改一句就能再试；新稿下方能读到当时的要求。
- 负面：要求不进入摘要与后续历史，下一次模型看到的仍是同一条大纲加最近情节；`messages.jsonl` 多一个可选字段；「重写要求」与选区改写的「改写要求」语义相近但粒度不同，文档里必须分开说。

## 被否决的方案

- **把要求存进 `session.json` 或单独文件**：生命周期与那一稿不一致，删除、重写、导出都要同步处理两处。
- **用模态对话框收集要求**：盖住正文、离开阅读位置，与项目现有的就地编辑习惯冲突。
- **让要求替换大纲**：与「复用已落盘大纲」直接冲突，失败后也没有原大纲可以回退。
- **把要求当作 system 指令拼进契约**：契约是全场不变的用户不可编辑层，一次性意图不该混进去。
