# 0005 · 开演后追加参演角色

- 日期：2026-11-13
- 状态：已采纳

## 背景

演员表在开戏时一次选定（`POST /api/sessions` 的 `cast`）。但一场戏可能写很多回合，导演常常在写到一半才发现需要一张新卡：一个还没登场的关键配角、临时想演的路人、或者刚在角色页建好的新人物。此前唯一的办法是重开一场戏——已有剧情、状态与摘要全部丢掉。

## 决策

1. **只增不减。** 新增 `POST /api/sessions/:id/cast`，body `{ cardId }`，把一张卡追加到 `session.json` 的 `cast`。不提供移除（理由见下）。重复添加幂等：不重复记录，也不更新 `updatedAt`。
2. **从下一回合起生效。** 每回合生成时按 `cast` 现读演员表，所以加入不触发重新生成、不改写任何已落盘的回合，也不重新计算状态。已写下的情节与摘要保持原样。
3. **不回溯、不复制。** 新角色不自动套状态模板，也不把角色卡内容复制进会话；卡库仍是唯一来源，右栏给它显示空状态区与「＋ 加状态 / 选模板」。
4. **入口在右栏。** 「参演角色」头部右侧加「＋ 加角色」，打开对话框只列卡库里还没参演的角色，点一下即加入；对话框保持打开，方便连着加。卡库为空时给「去『角色』页」入口。
5. **加入后给一句提示。** 告诉导演新角色从下一回合起进入演员表、想让它出场就在下一句大纲里交代。

## 理由

- **只增**：演员表只在生成时被读取，不记录「角色从第几回合开始在场」这样的区间。一旦允许移除，旧情节里仍有这个角色、旧状态记录仍指向它、摘要也可能提到它，而演员表却说它不在场——三者对不上。只增让这条边界保持单向、可解释。
- **下一回合起生效**：重写历史回合不是这次操作的意图；按时间线往后生效不需要给旧回合打补丁，也不会让已生成的选项与状态失效。
- **不自动套模板**：「这个角色该看哪些状态」是导演的判断，代码替他选一份模板反而要再改。空状态区本身已经提示可以加状态或选模板。
- **幂等**：对话框里连点、网络重试都是常见情况，重复加不该报错也不该产生重复记录。

## 后果

- 正面：不用重开戏就能加人，旧剧情、状态与摘要都不受影响；加人是一次轻量的本地写盘，不调用模型。
- 负面：新角色在旧情节里没有铺垫，模型下一回合可能突兀地让人出场，只能靠界面提示让导演在大纲里交代；v1 不能移除角色，想减人只能重开一场戏。

## 被否决的方案

- **允许移除参演角色**：需要额外表达「角色从第几回合起离场」，否则历史、状态与演员表三方对不上；收益也小（不演的卡放着不影响 prompt 之外的任何东西）。
- **加人时自动重新生成最后一回合**：代价是一次完整模型调用，且导演没要求；需要换写法可以自己用带要求的重新生成。
- **把角色卡内容复制进会话目录**：卡库修改会与快照脱节，删除被引用卡的检查也会失效。
- **在创建会话的弹窗里反复改 cast**：那是开戏前的一次性选择，开演后再改没有「从下一回合生效」的时间语义。
