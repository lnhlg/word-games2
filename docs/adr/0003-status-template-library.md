# 0003 · 状态模板独立成库，套用取快照

- 日期：2026-11-13
- 状态：已采纳

## 背景

ADR 0002 把状态模板定成「这一场戏的私有物」：每场戏在 `session.json` 里自带 `statusTemplate`，AI 造出来的条目直接写进那场戏，换一场就得重造一遍。

导演用下来提出：模板应该**单独建**——建好一批（毒医验伤、悬疑对峙、双人对峙），开戏时在右栏给角色挑一份挂上。这就把模板从「会话的字段」变成了「工作区的实体」。

## 决策

1. **模板是工作区级资产**：`<workspace>/status-templates/<id>.json`，与 `characters/` 平级；id 由模板名清洗得出，改名不改文件名。
2. **会话里的 `statusTemplate` 仍是「本场生效的定义」**，`statusView` 继续读它，旧会话零迁移。新增可选字段 `statusTemplateIds`（`角色卡 id → 模板 id`），只记来源，用于界面显示「模板：毒医验伤」。
3. **套用是快照，不是引用**：选模板时把条目复制进这一场戏的 `statusTemplate[cardId]`；之后改模板不影响已经开演的戏。
4. **换模板 = 整份替换该角色的条目**；被替换掉的条目如果还有值，追加一条清空记录（沿用 0002 的规则）。`templateId` 传空表示清空这个角色的状态项。
5. **每个角色最多套一个模板；一份模板可以套给任意多个角色、任意多场戏。**
6. **AI 造模板挪到模板库页面**：可以挂一张角色卡当参考，也可以不挂（生成通用维度）。它仍然只给名称与说明，不给值。

## 理由

- **快照而不是引用**：状态值按场次存。引用的话，演到第三回合时模板加了一个条目，这个条目在这一场没有历史值；模板删了一个条目，旧值悬空；模板整个被删，已开的戏还要定义一个错误态。快照把这三件事一次性挡在门外，代价只是「想同步得手动重新套用」。
- **不改 `statusView` 的读取路径**：如果会话直接读模板文件，「本场生效的定义」就会依赖模板文件的当前状态，回滚、导出、注入都要多一跳。保留 `statusTemplate` 作为真相，把模板库降级成「素材来源」，改动面小得多。
- **模板独立于角色卡**：卡是无损导入的酒馆 V2 资产，一改状态就动卡文件，会和「导入零损耗」冲突（与 0002 同一条理由）。
- **一角色一模板**：允许多份合并会带来「两份都有好感度怎么办」「顺序谁先」这两个没有好答案的问题；真实需求里，一个角色想要更全的维度，改模板就行。

## 后果

- 正面：模板可复用；改模板不会悄悄改变已经开演的戏；旧的会话与角色卡一个字节都不用迁移。
- 负面：模板改了之后，已经套用它的戏不会自动跟上，要手动再选一次；`session.json` 里同时有定义与来源 id，理论上会不同步（来源只是标记，不影响渲染与注入）；左栏多一个视图、右栏多一个入口。

## 被否决的方案

- **引用模板**（会话只存 templateId，显示与注入都读模板当前内容）：改一处全变，但会把「演到一半模板变了」变成需要处理的错误态，见上。
- **模板存进角色卡 `extensions`**：跨戏复用行得通，但一改模板就动 V2 卡文件，且「同一张卡的两场戏用不同模板」没法表达。
- **模板存在应用数据目录**：换电脑或换工作区就丢，和「工作区即真相」的原则冲突。
- **每角色挂多个模板并合并**：冲突与顺序没有好规则。
- **套用时要求模板非空**：空模板套上去等于清空，语义混乱，接口直接 400 拒绝。
