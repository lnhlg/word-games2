# 0001 · 回合可改写：删除、重新生成、编辑与后续剧情选项

- 日期：2026-11-12
- 状态：已采纳

## 背景

剧场原本只支持「一条大纲 → 一次生成 → 追加落盘」，`SPEC.md` 明确写着 `messages.jsonl` 只追加、不改写。导演实际使用后提出四件事：删掉一轮演坏了的戏、把最后一轮重写一遍、直接改 AI 回复里的错字或句子、以及在每段情节写完后拿到几条「接下来怎么演」的候选。前三件都要求磁盘记录不再是 append-only；第四件要求生成流程多一次轻量调用并把结果持久化。

## 决策

1. **`messages.jsonl` 改为可原地改写。** 读全量记录 → 在内存里改 → 以临时文件 + rename 原子写回。版本历史交给工作区所在的 git，不再留任何旧稿副本。
2. **删除与重新生成只允许最后一回合。** 删除整回合（导演大纲 + 情节），`session.json` 的 `turn` 回退一格，不重排编号。重新生成同样只针对最后一回合，用已落盘的大纲重跑，写出的新情节直接覆盖旧稿。**最后一回合取 `messages.jsonl` 里最后一条非 `system` 记录的回合号**，不再直接取 `turn - 1`：生成失败时回合号不前进、只留下一条大纲，这条大纲同样是最后一回合，删它不让 `turn` 回退，重新生成则补上该回合的正文。失败后改发新大纲时，新大纲顶替那条只剩大纲的记录，免得两条大纲挤同一个回合号。
3. **编辑允许任意回合。** 直接改写该回合 `narrative.text` 并记 `edited: true`；如果这一回合已经被压进 `memory.jsonl`，接口返回 `memoryStale: true`，界面提示「原文已进摘要，改动不会同步进旧摘要」。
4. **选项由正文之后的一次独立轻量调用生成。** 生成 3 条导演口吻的候选大纲，不传思考强度；失败静默，不影响正文。结果存进该回合 `narrative` 记录的可选字段 `nextOptions`，导出 Markdown 时不包含。
5. **选项只对最新回合可点。** 点击只把文本填进 composer，不自动开演；旧回合的选项保留展示但不可点。编辑或中断后该回合选项作废，不自动重新生成。
6. **接口命名。** `retry` 继续表示「失败后重发同一大纲」，是错误恢复；新接口一律用 `regenerate`，表示「主动重写成品」。SSE 增加 `next_options` 事件。

## 理由

- **只动最后一回合**：`memory.jsonl` 只压缩最早的一批回合，最近 8 回合永远以原文参与 prompt；最后一回合必然在这 8 回合之内。因此删除/重生成尾巴既不会让摘要过时，也不会让回合号与记忆区间错位，后续剧情也不会建立在被换掉的旧文本上。
- **编辑不限回合**：编辑不改变结构、不新增或删除回合号，是纠错性质的操作，限制它反而把「改个错字」变成「删了重写」。
- **覆盖不留旧稿**：如果每回合都留版本目录，磁盘形状、prompt 选择、界面入口都要跟着膨胀；git 本来就能回答「上一版是什么」。
- **选项独立调用**：把选项塞进正文的同一次生成会污染小说正文的约束；用轻量调用单独生成，失败可以安全忽略。
- **选项存进 narrative 记录**：选项与它所属的情节同生共死，删除或重生成那一回合时不需要同步清理第二份文件。

## 后果

- 正面：导演能删除演坏的最后一轮、原地重写、纠正任意一段错字，并在每段末尾拿到三个不同方向的下一步；这些操作都不离开阅读位置。生成失败时不会卡住：那条只剩大纲的回合照样能重新生成或删除。
- 负面：`messages.jsonl` 不再是 append-only，外部工具若同时改写会与后端冲突（当前是单机单进程应用，可接受）。编辑已记忆回合后，摘要与原文会不一致，只能靠提示说明。删除与重生成只覆盖戏剧的尾巴，想换中间一段仍要走「删掉后面所有回合再重写」。

## 被否决的方案

- **每回合留版本文件/目录**：实现与界面成本高，git 已覆盖版本历史。
- **删除任意回合并重排编号**：回合号同时是 `memory.jsonl` 的区间键与历史窗口的切分依据，重排会让摘要区间错位、历史拼错。
- **选项单独存 `options.jsonl`**：生命周期与情节不一致，删除、重生成、编辑都要同步两处，容易漏。
- **编辑走「先删后重写」**：一次错字修正要触发一次完整模型调用，成本与延迟都不合适。
