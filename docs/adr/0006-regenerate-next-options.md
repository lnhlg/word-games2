# 0006 · 单独重生成后续剧情选项

- 日期：2026-11-13
- 状态：已采纳

## 背景

ADR 0001 把「接下来可以怎么演」做成正文之后的一次轻量调用，结果写进 `narrative.nextOptions`，界面只展示、点击填入 composer。问题是这批选项只有一次机会：模型没给出 JSON 就空着；给出的三条不合口味，导演也没有重来一次的入口——除非把整回合重新生成，代价是一次完整的正文调用，还会把已经满意的正文一起换掉。

## 决策

1. **新增独立接口。** `POST /api/sessions/:id/turns/:turn/options`，只为最后一回合生成三条候选，覆盖该回合的 `nextOptions`，不追加。
2. **只读最后，不读整段。** 输入是这一回合的导演大纲、情节结尾 1200 字、各角色当前状态与视角；已有一批选项时附带「上一批」，要求换不同方向。
3. **不动正文、不动状态。** 只调用一次模型、只取 options，不跑状态更新；不产生新回合，不改 `session.json` 的 `turn`。
4. **只接受最后一回合。** 旧回合后面已经有剧情，选项要么与后文冲突，要么点了接不上；这一回合只有大纲、没有情节时也拒绝——没有「结尾」可以接。
5. **失败不破坏现状。** 模型没给出可用结果或调用失败时返回 400，原有 `nextOptions` 保持不动。
6. **入口在选项区。** 最新回合的选项标题右侧「换一批」；没有选项时显示「＋ 想几条接下来可以这么演」。生成期间禁用编辑、重新生成、删除与选区改写，避免和 `messages.jsonl` 的并发写入打架。

## 理由

- **单独调用，不并入 extras**：extras 的 prompt 要求同时给出状态更新，只为换选项再跑一遍会多花一次状态推理，也容易把状态写脏——单独生成选项本就不该碰状态。
- **覆盖不追加**：界面上只有最新回合的选项可点，6 条里挑 3 条可点会让人分不清哪批有效；「换一批」的语义本来就是替换。
- **给结尾不给全文**：选项只需要接住「现在」，整回合塞进去既贵，又容易让模型回头重写已经发生的事。
- **带上上一批并要求不同**：否则「换一批」经常换出同一件事的三种说法。

## 后果

- 正面：正文后的自动选项失败时不必重写整回合就能补上；对方向不满意可以低成本换一批；选项与状态彻底解耦，不会因为重想选项而产生第二次状态变更。
- 负面：模型仍可能给出方向雷同的三条；覆盖后没有撤销（旧一批只能靠记忆或 git 找回）；多了一个只服务界面的接口。

## 被否决的方案

- **复用 `generateTurnExtras` 并丢弃 status**：多一次状态推理的 token，也可能让模型按「要更新状态」的思路去写选项；语义上不干净。
- **追加到现有选项（3+3）**：界面与可点规则都要改，且「哪批是新的」没有稳定表达。
- **允许为任意回合生成选项**：旧回合的选项与后续剧情冲突，点击填进 composer 也接不上，还会诱导导演倒回去改戏。
- **走 SSE**：一次返回三条 JSON，不需要流式；普通请求还能直接带回落盘后的消息列表。

## 补充（同日）：给这一批一个方向

单独换一批上线后，方向仍由模型自己挑。导演常常知道「想往哪推」——让某人出场、引出某条线索、把气氛压下来——但没有地方说。

- **请求可带 `idea`。** `POST /turns/:turn/options` body 增加可选 `{ idea }`，≤300 字；留空表示不限定方向，保持原来一键换一批的行为。
- **注入位置在 user 消息里。** 想法作为【导演的想法】排在情节结尾之后、角色状态与上一批选项之前；system 要求三条都朝这个想法展开，但不能违背已经发生的情节，也不要在一条选项里塞进太多转折。
- **想法不落盘。** 它只作用于这一次生成，不写进 `narrative`、不改大纲；覆盖后无法回看上一批是按什么想法生成的，这是为了不给消息格式再加字段。
- **入口是展开式输入框。** 点「换一批」先在选项下方展开一个小输入框，Enter 提交、Esc 收起，留空直接提交即不限定；失败时输入框保留。

理由：一句话把方向说清楚，比在若干次重掷里碰运气便宜；它只是一次性意图，不该进入大纲或 system 契约。代价是模型仍可能理解偏，且想法本身不被记录。

## 补充（同日）：失败与容错

上线后真实模型偶尔不按 JSON 输出（先写一段解释、或用代码块、或干脆漏掉 `options`），接口直接回「模型这次没给出选项」，导演只能反复点重试。

- **解析先 JSON、后按行兜底。** 先认 `{"options":[...]}`、代码块包裹、裸数组；都失败时，收带编号/项目符号的短句（至少两条），或恰好三行并列的短句。太短、太长、以冒号结尾的行都不算选项。
- **失败自动再请求一次。** 第二遍在原对话末尾追加「只输出 JSON，不要解释、不要代码块」的纠正话；两次都为空才返回失败。
- **错误码改为 502。** 这是模型侧问题，不是请求参数问题；前端同时改为优先展示后端 `{ error }` 文案，导演看到的是「模型这次没给出选项，再试一次」而不是 `400 Bad Request: {...}`。
- **记日志。** 每次解析失败都把原始输出前 400 字打到控制台，方便下次定位是不是模型格式漂移。
